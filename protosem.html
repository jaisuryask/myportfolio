// IoT session

A smart-home and smart-lab build on an ESP32 in five tasks. It starts with a web page on the local network, moves to MQTT and voice control, and ends with a Firebase dashboard for the RAC lab with sensors, history and manual and automatic modes.

  • ESP32
  • HTTP
  • MQTT
  • Adafruit IO
  • IFTTT
  • Google Assistant
  • Firebase
  • DHT11
  • LDR
  • Relay module
TASK 01

Control an LED over HTTP

The ESP32 joins the local Wi-Fi and runs a small web server. A page in the browser toggles the onboard LED. HTTP works well for an occasional command, but the browser has to ask every time, so it cannot push updates on its own.

Browser → HTTP request → ESP32 web server → LED
View task 1 in detail →
TASK 02

Switch a bulb from anywhere with MQTT

Control moves to the cloud. A dashboard on Adafruit IO publishes MQTT messages and the ESP32 subscribes to them. A relay module switches the mains bulb so the 230 V side stays isolated from the microcontroller. The task also covers MQTT quality of service levels 0, 1 and 2.

Dashboard → Adafruit IO → MQTT → ESP32 → Relay → Bulb
View task 2 in detail →
TASK 03

Add voice control

A spoken command goes through a chain of services before it reaches the relay. Each hop adds a little delay, so the interface shows feedback while the bulb catches up.

Google Assistant → IFTTT webhook → Adafruit IO → MQTT → ESP32 → Relay
View task 3 in detail →
TASK 04

Build a web dashboard

A web app on Firebase with email and Google sign-in. It listens to the database in real time and shows temperature, humidity and light. It has Manual and Automatic modes, a saved LDR threshold, a history table and CSV export.

Firebase Hosting → Authentication → Realtime database → Dashboard
View task 4 in detail →
TASK 05

IoT control of the bulb, all together

Everything combined: a DHT11 and an LDR feed the ESP32, Firebase carries the data, and a web dashboard sets the bulb to Manual or Automatic. The page documents the pins, firmware, data model, tests and what remains. Videos show the bulb switching in Manual and Automatic mode. The sketch supplied with the report does not yet contain the read-back, so the demo version still needs documenting.

DHT11 + LDR → ESP32 → Firebase → Dashboard → Relay and bulb

// Debugging notes

Relay logic is reversed

The relay board in Task 2 switches on a LOW signal, so the code writes LOW for ON and HIGH for OFF. Checking the polarity first avoids a bulb that does the opposite of the button.

A paid plan for web requests

In Task 3 the IFTTT web request action needed a paid plan. The Adafruit IO action does the same job on the free plan.

Secrets in screenshots

Wi-Fi passwords and an Adafruit IO key showed up in early screenshots. They were covered before publishing, and exposed keys need to be regenerated.

Dashboard ahead of the firmware

In Task 5 the dashboard writes the light state, mode and threshold, but the sketch supplied with the report does not read them back. The demo version that does must be written up next.
